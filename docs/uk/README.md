Якщо щось тут розходиться з англійськими файлами, правильні англійські.

## Що ми робимо

Інтерактивний атлас змін земної поверхні за даними радара **NISAR**. Одна **таблиця** — це одне місце і один тип змін:
- Мехіко, що опускається;
- зсув у долині Лангтанг (Непал);
- ритм полів Центральної долини (Каліфорнія);
- землетрус у Панамі;
- «Земля дихає»: підняття купола над Свартсенгі (Рейк'янес, Ісландія) і дайка 10.11.2023. Це окрема зібрана сторінка `web/reykjanes-scroll.html`; конвеєр аналізу лежить у `scripts/reykjanes/`, математика для команди — у `docs/uk/reykjanes-math.html`.

Ми малюємо не веселковими смугами, а штрихами, як на гравюрах XIX століття (Дюфур, Леман). Кожна таблиця чесно каже, наскільки вона впевнена.

## Запуск (однаково для всіх)

1. Встановити [uv](https://docs.astral.sh/uv/) і клонувати репо **в коротку теку**, наприклад `C:\sars`. Назви файлів NISAR довгі (~125 символів), а Windows обмежує шлях 260 символами.
2. `uv sync`. Додаткові групи: `--group ml` (PyTorch, zuko) для ML-експериментів і `--group research` (shapely, osmium, pyproj, scikit-fem) для скриптів Рейк'янесу. Потрібні групи називайте в одному виклику, бо `uv sync` видаляє пакети груп, яких ви не назвали.
3. **Токен Earthdata**, один раз:
   - увійти на https://urs.earthdata.nasa.gov, натиснути Generate Token;
   - зберегти токен **одним рядком** у файл `C:\Users\<ви>\.edl_token` або в змінну середовища `EARTHDATA_TOKEN`.

   Кожен користується своїм акаунтом. Токен не можна комітити, вставляти в чати, документи чи issues і показувати Claude.
4. Перевірка: `uv run sars doctor`, потім `uv run python tests/smoke.py` (без інтернету, ~15 с).

## Основні команди

```bash
uv run sars sites                         # які є таблиці, що вже скачано, чи зібрано
uv run sars fetch mexico-city-asc --dry-run   # що буде скачано і скільки
uv run sars fetch mexico-city-asc         # усі дані таблиці; можна перервати й продовжити
uv run sars build mexico-city-asc         # зібрати шари для вебу -> web/data/mexico-city-asc/
uv run sars serve                         # відкрити http://localhost:8765/?scene=mexico-city-asc&theme=scroll
```

Інтерфейс мапи англійською за замовчуванням. Для української додайте до адреси `&lang=uk`.

## Як влаштовані дані

- `sars fetch` читає з кожного файлу NISAR (1–25 ГБ) лише вікно над таблицею, тобто мегабайти. Вікна кешуються в `data/raw/nisar_cache/`, і вдруге їх уже не качають.
- Пари знімків для кожної таблиці зафіксовані в `sites/<таблиця>.lock.json`, тому всі будують з тих самих даних.
  - Перевірено на чистому клоні: вікна NISAR і рельєф збігаються байт у байт.
  - Трохи може відрізнятись лише OpenStreetMap, бо це живі дані.
- Тека `data/` не потрапляє в git. У git лише зібрані таблиці `web/data/`, вони потрібні для GitHub Pages.
- Усі джерела, ліцензії, формати файлів і що потрібно кожній таблиці описані в [docs/data-guide.md](../data-guide.md).
- Особливий випадок — Central Valley: для шару полів потрібні два додаткові кроки, вони описані в тому ж гайді.

## Правила

1. **Токени й паролі** — тільки у вас, не в репо і не в чатах.
2. **Дані** — тільки через `sars fetch`. Перш ніж качати щось більше за ~1 ГБ, скажіть команді.
3. **Попередня реєстрація.**
   - Перш ніж запускати тест, на якому стоятиме твердження на таблиці, запишіть прогноз і пороги «пройшов / не пройшов» у `notes/experiments.md`.
   - Пороги після результату не змінюємо.
   - Те, що знайшли вже потім, позначаємо як **post-hoc**.
4. **Чесні таблиці.** Слабкий сигнал малюємо блідим, числа даємо з похибкою, провалені тести не ховаємо.
5. **Мова.** Код, коментарі, коміти, документація і все для журі — англійською. Тексти на мапі двомовні: `{ "en": ..., "uk": ... }`.
6. **Робочий цикл:**
   - гілка `<ім'я>/<тема>`;
   - smoke-тест;
   - pull request: GitHub сам вставить чек-лист, пройдіть його (пояснення в [CONTRIBUTING.md](../../CONTRIBUTING.md#before-you-open-a-pull-request));
   - хтось із команди дивиться;
   - злиття.

## Як додати нове місце

1. `uv run sars new my-place --bbox W S E N --direction ASCENDING --height <типова висота рельєфу, м>`
2. `uv run sars search my-place` (що є над місцем), потім `uv run sars fetch my-place` і `uv run sars build my-place`.
3. Відкрити `http://localhost:8765/?scene=my-place&theme=scroll` і налаштувати JSON таблиці.
4. Написати сторінки в `sites/my-place.story.json` і опублікувати їх: `uv run sars story my-place`.

Ідея для «рідного міста»: висхідний трек NISAR 42/26 покриває Дніпро, дно Каховського водосховища і Кривий Ріг. Деталі в `notes/research-resources-2026-11-13.md`.
